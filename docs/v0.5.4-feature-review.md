> 目标：修复标题字体不随设置缩放；支持 Markdown 图片显示与点击放大；自动识别裸 URL；修复冲突状态下 git discard 无效。

## 一、Bug Fix：标题字体不跟随字体设置缩放

**现象**：用户调整字号（XS/S/M/L/XL）时，正文段落字体缩放正常，但 `h1`/`h2`/`h3` 等标题字体无变化。

**根因**：`setFontSize` 通过 `document.body.style.fontSize = size + 'px'` 设置 body 字号。但 `editor.css` 中标题使用**绝对像素**值（`h1: 28px`、`h2: 22px`…），CSS 绝对单位不响应父元素字号变化。

**修复方案**：将 `editor.css` 中标题的 `font-size` 从绝对 `px` 改为相对 `em`（以 body 字号为基准）：

| 元素 | 现在 | 修改后 | 默认效果 (16px) |
|------|------|--------|----------------|
| h1 | 28px | 1.75em | 28px → 随 body 缩放 |
| h2 | 22px | 1.375em | 22px |
| h3 | 18px | 1.125em | 18px |
| h4/h5/h6 | 16px | 1.0em | 16px |

`code`/`pre` 字号保持绝对值（代码可读性不需随正文缩放）。

同时需修正 `inlineEditorHTML()` 中的 fallback CSS（与 `editor.css` 同步修改）。

**涉及文件**：`editor.css`、`MarkdownEditorView.swift`（inlineEditorHTML fallback）

## 二、Feature：Markdown 图片显示 + 点击放大

### 2.1 图片显示

**现象**：Markdown 中 `![alt](./image.png)` 的图片不显示。

**根因**：
1. WebView 通过 `loadFileURL(htmlURL, allowingReadAccessTo: htmlURL.deletingLastPathComponent())` 加载，读取权限仅限 bundle 目录，无法访问 Documents 目录中的仓库文件。
2. 相对路径 `./image.png` 相对于 bundle 中的 `index.html` 解析，指向错误路径。

**修复方案**：

**Step 1 — 扩展 WKWebView 读取权限**：

```swift
// MarkdownEditorView.makeUIView
let docsURL = FileManager.default.urls(for: .documentDirectory, in: .userDomainMask).first!
webView.loadFileURL(htmlURL, allowingReadAccessTo: docsURL)
```

**Step 2 — 传递 basePath，JS 端解析相对路径**：

在 `setContent` bridge payload 中增加 `basePath`（当前文件所在目录的 `file://` URL）：

```swift
// loadFileContent() 中
let basePath = parent.fileURL.deletingLastPathComponent().absoluteString
let js = """
    window.bridge.receive({
        action: 'setContent', version: 1,
        payload: { markdown: \(jsonString), basePath: '\(basePath)' }
    });
"""
```

在 `editor.js` 的 `markdownToHTML` 图片处理中，对相对路径进行解析：

```js
// 图片：将相对 src 解析为绝对 file:// URL
html = html.replace(/!\[([^\]]*)\]\(([^)]+)\)/g, function(_, alt, src) {
    if (currentBasePath
        && !src.startsWith('http')
        && !src.startsWith('data:')
        && !src.startsWith('file://')) {
        src = currentBasePath + (src.startsWith('/') ? src : src);
    }
    return '<img src="' + src + '" alt="' + alt + '">';
});
```

同步更新 `reloadContentIfEmpty` 也传递 basePath。

### 2.2 点击图片放大（双指缩放）

**操作**：在预览模式下点击图片，全屏展示该图片，支持双指 pinch 放大缩小，点击空白区域或滑动关闭。

**实现**：

**JS 端**：在预览模式点击事件中，优先检测 `<img>` 被点击：

```js
// editor.js — click 捕获阶段（useCapture: true）
editor.addEventListener('click', function(e) {
    if (currentMode === 'preview') {
        const img = e.target.closest('img');
        if (img) {
            e.preventDefault();
            e.stopPropagation();
            sendToNative('imageClicked', { url: img.getAttribute('src') || '' });
            return;
        }
        const anchor = e.target.closest('a[href]');
        if (anchor) { /* 现有逻辑不变 */ }
        sendToNative('modeChangeRequested', { mode: 'edit' });
    }
}, true);
```

**Swift 端**：
- `MarkdownEditorView` 增加 `var onImageClicked: ((String) -> Void)?` 参数
- `Coordinator.userContentController` 处理 `imageClicked` action，回调 `onImageClicked`
- `MarkdownEditorScreen` 增加 `@State private var imageViewerURL: URL?`，监听回调后赋值
- 使用 `.fullScreenCover(item: $imageViewerURL)` 展示 `ImageViewerScreen`

**ImageViewerScreen**：`UIViewRepresentable` 包装 `UIScrollView` + `UIImageView`，支持缩放：

```swift
struct ImageViewerScreen: View {
    let imageURL: URL
    @Environment(\.dismiss) var dismiss

    var body: some View {
        ZStack(alignment: .topTrailing) {
            ZoomableImageView(url: imageURL)
                .ignoresSafeArea()
            Button { dismiss() } label: {
                Image(systemName: "xmark.circle.fill")
                    .font(.title)
                    .padding()
            }
        }
        .background(.black)
    }
}

struct ZoomableImageView: UIViewRepresentable {
    let url: URL
    func makeUIView(context: Context) -> UIScrollView {
        let scrollView = UIScrollView()
        scrollView.maximumZoomScale = 6.0
        scrollView.minimumZoomScale = 1.0
        scrollView.showsHorizontalScrollIndicator = false
        scrollView.showsVerticalScrollIndicator = false
        scrollView.backgroundColor = .black
        let imageView = UIImageView(image: UIImage(contentsOfFile: url.path))
        imageView.contentMode = .scaleAspectFit
        imageView.frame = scrollView.bounds
        imageView.autoresizingMask = [.flexibleWidth, .flexibleHeight]
        scrollView.addSubview(imageView)
        scrollView.delegate = context.coordinator
        context.coordinator.imageView = imageView
        return scrollView
    }
    func updateUIView(_ uiView: UIScrollView, context: Context) {}
    func makeCoordinator() -> Coordinator { Coordinator() }
    class Coordinator: NSObject, UIScrollViewDelegate {
        var imageView: UIImageView?
        func viewForZooming(in scrollView: UIScrollView) -> UIView? { imageView }
    }
}
```

**涉及文件**：`editor.js`、`MarkdownEditorView.swift`、`MarkdownEditorScreen.swift`（新增 `ImageViewerScreen` 或单独文件）

## 三、Feature：自动识别裸 URL 并支持点击跳转

**现象**：Markdown 文档中直接写的 URL（如 `https://example.com`），在预览模式下不是可点击链接。

**分析**：现有 `markdownToHTML` 仅处理 `[text](url)` 格式的 Markdown 链接，不处理裸 URL。点击链接的 bridge 事件（`linkClicked`）已有完整实现，只需让裸 URL 渲染为 `<a>` 标签即可。

**修复方案**：在 `markdownToHTML` 中，处理完 `[text](url)` 链接之后，对剩余文本中的裸 URL 自动添加超链接：

```js
// 放在 Markdown links 转换（[text](url) → <a>）之后
// 自动识别裸 URL（不是已有 href/src 属性值的一部分）
html = html.replace(/(?<![="'(])https?:\/\/[^\s<>"')\]]+/g, function(url) {
    return '<a href="' + url + '">' + url + '</a>';
});
```

`htmlToMarkdown` 的 `<a>` 处理中，若 `inner === href`（即链接文字就是 URL 本身），则输出裸 URL 而非 `[url](url)` 格式：

```js
case 'a':
    const href = child.getAttribute('href') || '';
    result += (inner.trim() === href.trim()) ? href : '[' + inner + '](' + href + ')';
    break;
```

**预期效果**：
- `https://example.com` → 蓝色可点击，点击后系统浏览器打开
- `[点击这里](https://example.com)` → 保持原有行为
- 已有 `href/src` 属性中的 URL 不被二次处理

**涉及文件**：`editor.js`

## 四、Bug Fix：git 冲突后 discard 无效

**现象**：当 git 面板显示冲突状态（`SyncState.conflict`，即本地有修改 + 远端有新提交），对已修改文件执行 Discard 操作无效。

**根因分析**：`discardChanges` 对 `.modified` 文件的处理流程：

1. 优先从 `.originals/{path}` 恢复（仅当用户曾查看 diff 时才有缓存）
2. 若无缓存，从 GitHub 拉取 `snapshot.headCommitSHA` 处的文件内容

**Bug 1 — headCommitSHA 为空**：旧版 `RepoMetadata` 迁移到 `RepoSnapshot` 时（`RepoSnapshot(from: metadata)` 初始化器），`headCommitSHA` 被设为 `""`（见 `GitStatus.swift:22`）。此时 `getFileContent(path:ref:"")` 请求 GitHub API 会返回错误，导致 discard 失败并显示 error alert。

**Bug 2 — .originals/ 已被 commit 流程清除**：用户 commit+push 后，`.originals/` 缓存被主动清除（`GitService.swift:408-409`）。若用户再次编辑后出现冲突，此时 `.originals/` 为空，直接触发 Bug 1。

**修复方案**：

在 `discardChanges` 中，当 `headCommitSHA` 为空时回退到 `defaultBranch`：

```swift
// GitService.discardChanges
let ref = snapshot.headCommitSHA.isEmpty ? repo.defaultBranch : snapshot.headCommitSHA
let originalData = try await provider.getFileContent(
    owner: owner, repo: repoName,
    path: change.path, ref: ref
)
```

同时，在 `.originals/` 恢复路径结束后，将 `.originals/` 文件的内容 hash 与快照对照，若不一致则更新快照（防止 status() 重复判定为 modified）：

实际上，只要 `.originals/` 中存储的是从 GitHub 获取的原始字节，其 hash 必然与 `snapshot.files[path].originalContentHash` 一致（两者都来源于同一次 `getFileContent` 调用）。因此无需额外修正快照。

**核心改动**（仅 1 行）：

```swift
// Before:
let originalData = try await provider.getFileContent(
    owner: owner, repo: repoName, path: change.path, ref: snapshot.headCommitSHA
)
// After:
let ref = snapshot.headCommitSHA.isEmpty ? repo.defaultBranch : snapshot.headCommitSHA
let originalData = try await provider.getFileContent(
    owner: owner, repo: repoName, path: change.path, ref: ref
)
```

**涉及文件**：`GitService.swift`
