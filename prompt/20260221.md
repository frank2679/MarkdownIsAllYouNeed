## 本轮目标：存储优化（v0.4.0）

### 问题根因

每个 clone 的仓库，文件被存储了**两份**：

```
Documents/repos/{owner}/{repoName}/
├── {实际文件}          ← 工作目录
├── .originals/
│   └── {完全镜像}     ← 原始副本（用于 diff）
└── .repo-metadata.json
```

用户反馈：clone 了 2 个仓库（理论 104MB），实际占用 226MB。
`.originals/` 是主要原因（约 2 倍空间）。

### 关键发现

- `status()`（变更检测）**不依赖** `.originals/`，使用 `RepoSnapshot.files[path].originalContentHash` 做 hash 比对
- `diff()`（差异视图）**依赖** `.originals/`，读取原始文件内容做对比
- `TrackedFile` 已保存 `sha`（GitHub blob SHA），可按需从 API 拉取原始内容

### 解决方案：Lazy `.originals/`

1. **clone 和 pull 不再写 `.originals/`** → 立即减少约 50% 存储占用
2. **新增 `diffAsync(path:repo:token:)`** → 查看 diff 时按需从 GitHub 拉取原始内容，并缓存到 `.originals/`
3. **commit 后清理缓存** → evict 已提交文件的 `.originals/` 条目（提交后文件变为新基线）
4. **`GitPanelView` 改用 async diff** → 点击查看 diff 时触发异步拉取

### 不影响的功能

- 变更检测（`status()`）：完全不受影响
- 文件操作（新建、重命名、删除、移动）：不受影响
- Commit & Push 流程：不受影响
- 文件树展示：不受影响
